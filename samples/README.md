# Sample outputs: synthetic and demo data only

> **Everything in this folder is synthetic or demo data.** The jobs come from demo job sites made for scraping practice. The candidates are invented people, parsed from synthetic resume PDFs. No real resume, real person, email address or phone number is included.

## How these files were made

- Made on 22 November 2026 from the running Docker stack, with FITSCAN's own export code in `backend/app/services/export.py`. The columns, cell formatting, CSV quoting and JSON models are the same as the export endpoints. Only database reads were used: no crawl, no resume upload and no match run, and nothing in the database was changed.
- The matches are the stored results of the latest match run (`computed_at` 2026-11-22T13:50:44Z, default weights 70 / 15 / 10 / 5). No score was recomputed for this folder.
- Two filters make these files differ from a plain export:
  1. **Candidates.** Only the 5 synthetic candidates are included (their emails use the reserved `example.com` domain). Other resumes in the database are left out.
  2. **Matches.** Only demo jobs are included. The database also holds 20 real public job postings (one Greenhouse and one Lever board, see [`DATA_SOURCES.md`](../DATA_SOURCES.md)), which are left out so that this folder holds demo data only. Ranks 1–10 are therefore positions among the 108 demo jobs, in the application's order: score, then text similarity, then the required-skill ratio, then job ID. In the application, a candidate's top 10 can include real postings as well, so a demo job's rank there can be lower; its score is the same.

## Reading the files

- **CSV:** UTF-8, comma-separated, with a header row and standard quoting (a cell with a comma, a quote or a line break is quoted). Lists are joined with `"; "`, and each skill in the match table carries its level, for example `Go (required); Kubernetes (nice-to-have)`. A cell that could start a spreadsheet formula gets a leading `'`, which is why phone numbers appear as `'+919876543210`.
- **JSON:** one array of objects, with lists and nested objects kept as they are (skills, education, the score `breakdown`).
- **Scores** are rounded to 2 decimals, as in every export. The database stores them unrounded and ranks by the exact value.
- **`listing`** in the jobs files is `demo` for every row. `industry` is the stored industry (see "How crawling works" in the [README](../README.md)).

## What is invented

- **Candidates:** names, emails (`@example.com`), phone numbers, universities and summaries were invented. Four of the five people are defined in `backend/tests`; Nikhil Joshi was made with the same generator for the hand check.
- **Fake Python Jobs:** company names, towns (for example "Martinezburgh, AE") and descriptions were generated by Faker. A skill word in a description is filler text, not a real requirement, and no candidate gets location points for those towns.
- **Mock site:** the 8 jobs, companies and the `careers.example.com` apply links were written for the project.

How each candidate's top 3 jobs were checked by hand is in the [README](../README.md#matching-hand-check-5-candidates).
